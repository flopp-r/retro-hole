# Retro Hole: guide for AI assistants and developers

This is the main guide for anyone, person or AI, who changes this project. Claude Code reads it through `CLAUDE.md`; other AI coding tools read `AGENTS.md` directly.

## Start here

**What it is.** Retro Hole is a 3D voxel pixel-art game in the style of hole.io, a sister to the owner's other games (Retro Rack, pool, and Retro Set, chess). You steer a hole across an endless, generated map. Anything smaller than the hole falls in; each thing eaten makes the hole bigger. There are 1,000 levels. The map has seven areas (village, forest, city, Jurassic Park, desert, arctic and volcano), rival holes (bots) that eat, grow, hunt and flee and can swallow you, and the further from the start, the bigger everything is. The view is isometric and from above. It is one self-contained web page, hosted on GitHub Pages from this repository. You count your kills and deaths, earn coins (from levels, from rival holes you swallow and from gold coins on the map) and spend them on skins for the hole and effects for eating (see Coins, skins and effects below). There are two ways to play, picked on the title screen: the normal game, and **Quick Game** (one fixed scale everywhere, no level cap, extremely fast growth: see Quick mode below). Single player for now; online play is planned (`HANDOVER.md`, section 4).

**Read in this order**
1. This file: how it works, the rules, how to test and ship a change.
2. `HANDOVER.md`: why things are the way they are, the measured numbers, the decisions still to make, and a dated list of changes.
3. `README.md`: how the owner puts it online, and what players see.
4. The code: `src/world.js` (the rules and the map, no screen), then `src/game.js` (everything in the browser). Both are split into sections marked `// ------ name`.

**Rules that must never be broken**
1. **`index.html` is built output.** Edit `src/`, run `node tools/build.js`, commit both.
2. **A clean console:** no errors, warnings or deprecated APIs.
3. **`main` is live.** Pushing to `main` deploys the site. Work on a branch, test first.
4. **`src/world.js` has no DOM and no three.js, and no `Math.random`.** Every choice takes the world seed, so the same seed gives the same map in the tests, the tools and (later) for two players online.
5. **Numbers that set the pace are measured, never guessed.** Changing growth, xp, what a thing is worth or how thick things are changes how long the climb takes: re-run `node tools/sim-pace.js` and record the table in `HANDOVER.md` (section 5).
6. **The repository is public.** Never commit personal details, passwords, tokens or keys.
7. **Online play will need both players on the same version** and the same seed (`HANDOVER.md`, section 4). Ask the owner before building it, and before any change to how the world is generated: changing it changes every map.

## Project conventions

- Explain changes in plain language, say what will change on screen, keep jargon out of summaries.
- UK English and metric units everywhere: in the UI, comments and messages. Sizes are shown in cm, m and km (`fmtLen`).
- Ask before large redesigns, and agree any other change first.
- Wording on screen: buttons and headings in Title Case and short, notes one factual sentence. No chatty asides.
- Code style: match the file you're in. Compact, comments only where the reason isn't obvious. No build step beyond `tools/build.js`, and no frameworks or npm packages in the game.
- Browser storage keys start with `retroHole.`: `retroHole.settings`, `retroHole.save`, `retroHole.saveQuick` (Quick Game) and `retroHole.profile` (coins, skins, kills and deaths). Wrap every access in try/catch.
- Every screen must fit a phone held sideways (760 x 340) without overlap.

## Commands

Only Node is needed (the browser tests also need Playwright with Chromium, which cloud sessions have).

- `node tools/build.js`: rebuild `index.html` after any change in `src/`.
- `node tests/world.test.js` and `node tests/skins.test.js` (`npm test` runs both): the rules and the map, and the skins. Must pass before pushing.
- `node tests/browser/run-all.js [words]` (`npm run test:browser`): builds, then runs the browser tests (all, or files whose names contain the words). Each file fails if anything reaches the console. Screenshots go to a temporary folder, printed at the end.
- `node tools/sim-pace.js [efficiency]`: the pace table (see `HANDOVER.md`, section 5).
- To look at the game: open `index.html` in a browser.

## Deployment

GitHub Pages serves the repository root at `https://flopp-r.github.io/retro-hole/` within a minute or two of a push to `main`, once the owner has switched it on (`README.md`). Browsers cache: tell the owner to press Ctrl+F5 after an update. The version at the bottom of the title screen (`const BUILD`, a fingerprint of the code) shows whether it has arrived.

## How changes are made

1. Agree the change with the owner first: explain the trade-offs, recommend one, then build what they pick.
2. Work on a branch. Edit `src/`, run `node tools/build.js`, run the tests, commit `src/` and `index.html` together.
3. Open a pull request into `main` only when the owner asks; squash-merge only when they say so.
4. Update this file, `HANDOVER.md` and `README.md` in the same change as the code. Notes go stale quietly; fix any that no longer match.

## Architecture

### The world (`src/world.js`)
- **Scale grows with distance.** `scaleAt(d) = 1 + d / D0` (D0 = 120 m): things 120 m out are twice the starting size, 240 m out three times. A hole that has grown to match meets the same kind of world wherever it is, so the map can go on for ever and no number runs away. `tierOf(d)` is the ring a distance falls in: ring `t` is where the scale is from 2^t to 2^(t+1) (0 to 120 m, 120 to 360 m, 360 to 840 m ...).
- **Levels** (`need`, `progress`, `radiusAt`, `xpFor`): 1,000 levels. The radius is 0.5 m at level 1 and 5,000 times that at the cap, and grows smoothly between levels: `radiusAt = 0.5 * 5000 ^ (((level - 1) / 999) ^ CURVE)` with `CURVE` 0.6, so it grows quickly at first (about 7% a level at level 2, 3% at level 10, 1.3% at level 100, half a per cent near the cap): a level 10 hole is 1.7 times as wide as the start, level 50 four times, level 100 eight. A level needs `0.27 * (1 + L / 25) ^ 1.1` xp. A thing gives `0.015 + (its radius / the hole's radius) ^ 2` xp, so the same thing is worth less to a bigger hole. `CUM` holds the xp where each level begins.
- **Swallowing:** a hole swallows things up to 92% of its own radius (`canEat`), once its centre is within `radius - 0.35 * thing's radius` of the thing's (`swallowDist`).
- **Plots: the framework every area follows.** The map is cut into square cells (32 m wide in ring 0, twice as wide in each next ring), and each cell is one **plot** of one area (`BIOMES`: village, forest, city, jurassic, desert, arctic, volcano) and one kind within it (`plotKind()`, 42 kinds): village homestead, farm, pasture, field, orchard, green, pond, meadow; forest dense, mixed, clearing, rocky, pond, grove (far out); city built, park, plaza, lot (car park); Jurassic Park jungle, paddock, nest, visitor, lagoon, compound; desert dunes, oasis, town, ruins, canyon, camp; arctic snowfield, pinewood, frozenlake, outpost, iglooville, glacier; volcano ashfield, lavaflow, crater, mine, forge, spires. `cellInfo(t, i, j)` gives everything the ground and the layout both need (area, kind, road on each side, the margins, `inner`, the pond) and is cached; `cellAt(x, z)` finds the cell of a point; `biomeAt()` is that cell's area. **Areas are big regions with a guaranteed minimum size** (`REGION`, `rawBiome()`): a jittered grid of region centres on the ring-and-sector map (5 to a turn, a ring row every factor of e^(1/1.06) in distance plus a floor of 150 m, so regions are as much bigger as they are far out), each centre has one area (15% city, 17% forest, 12% Jurassic Park, 13% desert, 12% arctic, 9% volcano, 22% village), and a point belongs to the nearest centre. Every centre in the first ring row is a village, so the start is one big village with natural edges (at least 150 m in every direction, typically 250 m), and nothing is cut into slivers. Regions near the start are at least about 400 m across (the first version used smooth noise, whose patches were as small as a few metres). A cell takes the area at its middle. The four cells round the start are fixed (`START_PLOTS`) so houses, animals and a green are in sight from the first step.
- **Roads** (`edgeRoad`, `STYLES`): roads run along cell edges, so each plot knows which of its four sides has a road (`road.w/e/n/s`: `'street'`, `'lane'`, `'trail'`, `'park'` (Jurassic Park's service road), `'track'` (desert), `'snowpath'`, `'ashpath'` or null). A line is a road along its whole length when its hash is under the road share of the busier area on either side (city 1.0, Jurassic Park 0.5, village 0.4, desert 0.35, arctic 0.2, forest 0.15, volcano 0.12), so city streets run through the whole city, lanes wander through villages and carry on into forests as trails, and a city meets a village where its streets end. The style is that of the area with the higher priority. Widths and verges are in units of the ring's scale (`1.5 * 2^t`), so they step up at ring edges and stay in proportion. No road runs within 45 m of the start. `groundColour()` colours the tiles from the same cell: road, pavement or verge, pond (water, ice or lava: `c.pond.liquid`), a lava river (`c.river`, kind `lavaflow`), crops, park, paving, and each area's own ground.
- **Layouts** (`LAYOUTS[area][kind](ctx)`): each plot kind has a layout that places things with the tools in `makeCtx()`: `add(id, x, z, opts)` (one thing: sized by where it stands, turned, and refused unless it is wholly inside the plot proper, not on the start, not in a pond and not overlapping anything), `scatter(ids, per100, rect)` (random places; the count is per 100 m2 at the start's scale, times `DENSITY`, 3.2), `ring(...)`, `fence(rect, gate)`, `frame(side)` (the plot's own frame: along the front, inward from it), `front()` (the side with a road), `pick(ids)` (one that is far enough out), `herd(id, rect, n, o)` and `herdSize()` (a herd of one species in a pen), `fence(rect, gate, fenceId)` (any kind of fence). `pondLayout(ctx, plants, {edge, life, rim})` makes a pool of any liquid with creatures on it (`water: true` lets a thing stand in a liquid or river; such things carry `wet`), and `treeFeet(ctx, trees, per, feet)` grows plants at the foot of any trees. A thing goes only where it belongs: the **city** has a pavement all round every block (lamps, street trees, bins, benches, hydrants, phone boxes, bus stops), a traffic light at each corner, cars, vans and buses in the lanes going the way traffic goes on the left, rows of buildings facing the street on all four sides (`frontage()`; low blocks near the start, taller further out, by `from`), a courtyard behind with trees, benches and pigeons, and sometimes a park (fountain, trees), a plaza or a car park in rows. Cars also stand parked along the kerbs. The **village** has houses facing their lane inside a fenced garden with a postbox at the gate and animals in the garden, farms (barn, farmhouse, silo, a fenced paddock with animals, chickens and tools by the barn), fenced pastures, fields with a scarecrow, orchards in rows, a green with a well and benches (a church far out), ponds with ducks and reeds. The **forest** has woods (ferns, mushrooms, stumps and logs at the foot of trees, squirrels, deer, foxes), clearings with a cabin, campfire, logs round it and a woodpile, rocky ground, ponds and groves of giant trees, with trees kept off the trails. **Jurassic Park** has jungle (ferns, eggs, compys, raptors), paddocks (an electric fence with a gate round a herd of one dinosaur species, a tour jeep inside, a watchtower), nesting grounds with a mother, the visitor centre (gift shop, gate, jeeps in rows), a lagoon with a wading brachiosaurus and swamp trees, and a laboratory compound with helipad, generators and cages. The **desert** has dunes (cacti, scorpions, lizards, camels), an oasis, a town of adobe houses facing the track round a market with a well (a mosque far out), ruins (rows of columns, obelisks, a sphinx, and from 840 m a pyramid), a canyon of mesas and arches, and a nomad camp. The **arctic** has snowfields (drifts, snowmen, wildlife), snowy pine woods, frozen lakes (penguins and seals on the ice, fishing huts), a research outpost, a village of igloos round a fire and glaciers of ice spires. The **volcano** has ash plains, lava flows (a river of lava with salamanders on its banks), a crater with a lava lake, mines (huts, a shaft, carts), a forge with ruined towers and spires of obsidian (a whole volcano far out). To add an area: an entry in `BIOMES`, a chooser in `plotKind()`, layouts in `LAYOUTS`, colours in `groundColour()`; its things in `TYPES`.
- **Things** (`TYPES`, from `def()`): each has an area (`biome`, for the catalogue), a natural radius `b` in metres at the start (194 things in all, the gold coin included), how far out it first appears (`from`), how fast it wanders (`walk`, m/s at the starting size; animals only) and its voxel model, boxes on a coarse grid (`P(width, height, depth, colour, x, y, z)`; models face -z, width along x). `model(ty)` scales the boxes so the circle round the footprint has radius `b`, and gives `hw`, `hd` (half the footprint's width and depth), which the layouts use to line things up. A thing's size where it stands is `b` times the local scale times 0.85 to 1.2 (a house in a garden: the plot's scale).
- **Cells** (`genCell(t, i, j, cull)`, `wantedCells()`): a cell is made from the seed alone. Everything in it is wholly inside it, belongs to its ring, and does not overlap anything else (boxes, not circles: `ex`, `ez` are each thing's half-size along x and z). `cull` leaves out things smaller than that radius, and they are kept as invisible ghosts while the cell is made, so what is left is exactly what it would be without `cull`. A penned animal carries its `pen`. `wantedCells()` lists the cells within a radius of the player, nearest first, skipping rings whose biggest thing would be a speck.
- **Rival holes** (`botSpec(c)`, `genCell().bot`, `xpForRadius(r)`): about one cell in five (`BOT_CHANCE`) has a bot, decided by the seed alone: its place in the cell, its name (`BOT_NAMES`), colour and how aggressive it is. Its radius is the starting radius times the local scale times a factor from 0.5 to 2.6 (so a hole of about the right size meets bots about its own size wherever it goes), and near the start (within 150 m) no more than 1.2. Two small, harmless bots live in two of the cells round the start (`START_BOTS`). `xpForRadius()` is the inverse of `radiusAt()`, so a bot made at a size has exactly that level.
- `setSeed()` and `getSeed()`: the world seed. **Changing the world's rules changes every map for the same seed.**

### Quick mode (`MODE`, `setMode()` in `src/world.js`; `startGame(fresh, mode)` in `src/game.js`)
- **What it is.** A second way to play, started from the title screen (Quick Game, Continue Quick, New Quick Game). Everything is one size everywhere and the hole grows extremely fast with no level cap. The normal game is unchanged: `world.js` holds a mode (`'normal'` or `'quick'`, `getMode()`), and `startGame()` sets it before any cell is made (the title screen always shows the normal world). Tests that switch to quick mode must switch back (`W.setMode('normal')`).
- **One scale.** `scaleAt(d)` is 1 at any distance, `tierOf` is always 0, `tierRange(0)` is `[0, Infinity]` and `cellSize(0)` is 32 m, so there is only ring 0 and every cell is the size of the first cell of the normal game. Roads, widths and layouts are the same as ring 0.
- **Areas are regions of one size** (`quickBiome(x, z)`): a jittered square lattice (`QUICK.SPACING` 360 m, `QUICK.JITTER` 0.4) of region centres, each with one area from the same shares as the normal game (`pickBiome()`); a point takes the nearest centre. The four centres round the start are villages, so the start is a big village (at least 250 m in every direction). Regions are the same size near and far.
- **Levels have no cap** (`MAXLV` and `MAXXP` are `Infinity`). `need(L)` is `QUICK.NEED + QUICK.NEED_K * L` (0.12 xp plus 0.002 a level), `cum(L)` the xp where a level begins, and `radiusAt(level, frac) = 0.5 * (1 + QUICK.A * (level - 1 + frac)) ^ QUICK.P` (A 0.8, P 0.6), so the radius is 7 m at level 100 (the size of the biggest buildings) and about 28 m at level 1,000, then keeps growing more slowly. `xpForRadius()` is its inverse, so a bot made at a size has exactly that level.
- **What still gets harder with distance.** Bots: `botScale(d)` is `1 + 13 * min(1, d / 1500)`, so a bot 1.5 km out is up to 14 times the starting size (`QUICK.BOT_X`), and the rarer kinds of thing still appear only from their `from` distance. The camera, bots, eating and everything else work as in the normal game.
- **The big-hole limit.** With one scale nothing is bigger than the biggest buildings (about 14 m across, and the biggest dinosaurs and giants), so a hole past about level 100 has nothing left to swallow but ever smaller things, and past about level 500 sees mostly dust. Levels go on (each worth less) because the owner chose no limit. A cap would be one number (`maxLv()`). `wantedCells()` shrinks its radius to the nearest 6,000 cells so a huge hole stays inside the budget.
- **UI:** `#wMode` shows "Quick Mode" under the area name; `lostCheck()` (the hint to return to the start) is off in quick mode, since nothing is out of reach; the "far" hint says what is different.

### Coins, skins and effects (`src/skins.js`; `COINS` in `src/world.js`; the profile and Skins screen in `src/game.js`)
- **Kills and deaths.** `H.kills` and `H.deaths` count this run (on the HUD as "Kills 0 / Deaths 0", kept in the save as `k` and `d`, back to 0 on a New Game). The totals for good are `PROFILE.stats.normal` and `.quick` (each game its own), shown on the Skins screen's Stats tab. A kill is swallowing a bot (`swallowHole()`); a death is being swallowed by one (`killPlayer()`).
- **Coins** are earned three ways and kept in `PROFILE.coins` (a number that may hold fractions; shown rounded down; "+N" shows by the HUD for a moment, `earnCoins()`). **Levels** (`levelPay(level)`): 1 coin plus 1 for every 5 levels, paid in `gain()` only for levels above the best this run (`H.best`, saved as `b`), so dying and climbing back pays nothing; in Quick Game a level pays 1/100 (`COINS.QUICK_LEVEL`), since levels come about 100 times faster. **Kills** (`killPay(victimRadius, timesBefore)`): 5 plus the swallowed bot's size level, divided by 1 plus how often that same bot has been swallowed before (`b.deaths`), so a bot that comes back after 25 s cannot be farmed. **Coins on the map** (`foundPay(holeRadius)`): 5 plus 5 times the square root of the hole's size level (10 coins for a new hole, 55 at level 100, 160 at level 1,000), a tenth of that in Quick Game. The "size level" (`sizeLevel(r)`) is the normal-game level of a hole that wide, so Quick Game's big holes are paid by size.
- **The gold coin** (`TYPES`: `coin`, biome `all`, radius 0.14 m) is an ordinary thing that a hole swallows, put down by `genCell()` after the plot's layout (`COINS.PER100`: about one or two in a plot; each tries 60 places, since plots are full), so every other thing stands exactly where it did. Coins scale with the plot like everything else, and are left out (`cull`) once a hole is much bigger than one.
- **Skins** (`SKINS`, 25 in five rarities with prices 150, 400, 1,000, 2,500 and 6,000; Classic is free): the ring's colours and how they are laid round it (`pattern`: solid, stripes, halves, thirds, checker, dash, gradient, in 48 segments), the pit's top and bottom colours, and `spin` (epic and legendary skins turn). `applySkin()` writes them into the player's own ring geometry (`ringSkinGeo`, non-indexed, one colour per triangle, wider than a bot's ring so the pattern shows) and pit (`pitSkinGeo`); `makeVisual(hex, own)` makes the player's visual. **Effects** (`EFFECTS`, 7: none free, then 300 to 4,000 coins): cubes thrown up where a thing falls in (`spawnBits()`, `bitsStep()`, an instanced mesh of 240 `BITS`), sized in hole radii so they look the same at every level, at most 6 throws a frame, none with reduced motion.
- **The Skins screen** (`#skins`, `renderSkins()`): opened from the title screen (`#bSkins`, which shows the coins) and the menu (`#bSkins2`). Tabs Skins, Effects and Stats; a card for each with a picture (`drawPreview()`), its rarity and Buy / Wear / Worn. Buying takes the price and wears it at once. Esc closes it (and only it). The profile is saved on buying and with the game's save (`profileDirty`). A saved profile is cleaned on loading (`K.validate()`): unknown ids dropped, nothing worn that is not owned, no negative coins. It is plain browser storage and can be edited by anyone: there is no online play to protect.
- **The pace of coins** is measured by `node tools/sim-pace.js` (columns "coins so far" and "coins/min: levels, found"); see `HANDOVER.md`, section 5.

### The game (`src/game.js`)
- **Rendering** (renderer + post): the scene is drawn small into a render target, then a shader adds outlines where the depth jumps, a vignette and, below full colour, Bayer dithering; the canvas is scaled up with hard pixel edges. Retro Set's pipeline, with an orthographic camera (depth is linear between `near` and `far`; `uEdge` is the depth jump, in metres, that makes an outline, 10% of the hole's radius, so small things keep their colour). `S.pixel` is game pixels per screen pixel (0 is Max). Colour management is off: colours appear as written.
- **Materials:** the ground's shader throws away every pixel inside every hole (yours and up to 12 bots': `uHoles`, `uNH`) and darkens each rim. The standing things' shader dissolves a thing by an amount `aFade` (0 to 1; one number per thing, in the pool), by throwing away pixels in the post filter's Bayer pattern. A pit (a dark open cylinder with a black floor) sits under the ground and is seen through the gap, and a ring with a dark edge is drawn over everything (yours yellow, each bot's its own colour): `makeVisual()`, `placeVisual()`, `VIS`.
- **Standing things** (`Pool`): one instanced mesh per kind of thing, shared by every cell; a thing is a slot, with its matrix and a brightness (the instance colour). Slots are freed when a cell is dropped or a thing has fallen. Each model's boxes get a vertex colour on every corner and no undersides.
- **The ground** (`updateGround()`): a field of flat tiles, about three quarters as wide as the hole (`2^round(log2(0.75 r))`), that keeps its tiles in place as it moves, so only the ones that come into view are rewritten. It is the same size whatever the level.
- **Cells in and out** (`plan()`, `makeCells()`): every quarter of a second, the cells within 32 hole radii are wanted; a cell is dropped only when it is neither wanted nor within 1.3 times that, and **everything wanted is always kept**, so a cell can never be made and dropped at the next look (which regrew what was eaten there). Missing cells are made 5 ms a frame (400 ms at the start), nearest first. When the budget of things (`OBJ_BUDGET`, 14,000) is spent, a nearer wanted cell takes the place of the farthest cell held, and only if that one is farther, so the held cells settle on the nearest ones. Things smaller than 5% of the hole's radius are not made. **Things you ate come back** when their cell is dropped and made again (by leaving and returning, never while you stand there).
- **Animals** (`wander()`): animals near the hole (within 22 radii) walk a little, stop, turn and go again, always inside their own cell (or their pen, for a penned animal), with a small hop at each step. Moved a frame at a time and only while the hole is near; far away they stand where the map put them. Eating works on their current place.
- **Nothing blocks the view** (`fadeStep()`, `inTheWay()`): a thing too big to eat (and taller than 0.8 hole radii) that stands over the hole, or between the camera and the hole, or just beside that line, dissolves to 80% while it is in the way and comes back when it is not (eased over a fraction of a second; at once with reduced motion). The test is a straight line from the hole's middle towards the camera through the thing's box, made 2.2 hole radii bigger all round. Things the hole can eat are never touched.
- **Rival holes** (`BOTS`, `botsStep()`, `botThink()`, `duels()`): a bot is made when its cell is loaded (`makeBot()`, in `mount()`; none on the title screen) and dropped with it. The nearest 12 alive bots (`ACTIVE`) are drawn, cut out of the ground and simulated; the others stand still. Every 0.2 s a bot thinks: it flees a hole that could swallow it (up to about 7 to 10 of that hole's radii away), hunts a hole it can swallow that is near (4 to 13 of its own radii, by how aggressive it is), otherwise goes for the thing worth most for its distance (`bestFood()`, within 14 radii), otherwise wanders. It moves at 0.6 of your speed times 0.6 to 1.2 by what it is doing, so you can outrun a bot up to about 1.4 times your size. It eats by the same rule as you (`eatFor()`), earns 0.2 of the xp a thing gives you (`BOT_XP`), and stops growing at 1.4 times the size its place suits within 150 m of the start and 3 times (`BOT_CAP`) further out (`botSetXp()`, so its level always matches its size). A hole swallows another when it is at least about 8% wider (`EAT_MAX`) and its middle is over it (`swallowDist`, `duels()`, `swallowHole()`): a bot you swallow falls in, gives you 3 times the xp of a thing that size, and comes back at its starting size 25 s later (`RESPAWN`); **if a bot swallows you** (`killPlayer()`) you lose half your xp (and the levels it gave), come back 10 of its radii away from it, and are protected for 4 s (your ring blinks; bots ignore you). A new game starts with 8 s of protection. On screen: a name and level over each active bot (`updateLabels()`: a red border if it could swallow you, green if you could swallow it) and a scoreboard of the biggest holes near you (`updateBoard()`).
- **Eating** (`eatFor()`, `fallStep()`): every thing within reach of a hole (yours or a bot's) that it can swallow and whose swallow distance is reached starts to fall (`startFall(o, c, hole)`: xp is given at once to that hole). It sinks with a growing speed, tips towards the middle and is released when below the ground. Things too big for the hole are left alone; the hole passes under them.
- **Steering** (`steer()`): the hole stays in the middle of the screen. The mouse steers towards the pointer (nothing under 6% of the screen's short side; full speed at 28%; not while over a button, and not after Play or Resume until the pointer moves) unless mouse steering is off (`S.mouse`: the M key, or Mouse Steering in Settings); WASD and the arrow keys steer too; on a touch screen, touch and drag. Directions are on the screen: up is away from the camera. Speed is 6.5 hole radii a second, but never less than that of a hole a quarter the size the place suits (`speedRef()`), so a small hole far out can walk home.
- **The camera** (`updateCamera()`): orthographic, from the south-east at 50 degrees, the view 7.6 hole radii from the middle to the top, so the hole is always the same size on screen and the world scales round it. On the title screen the hole sits low and to the right, clear of the buttons.
- **Screens:** `title` (the world behind it, with the hole playing itself), `play` and `pause`. The HUD: level, size, a progress bar, what has been eaten, the area and distance from the start. Hints appear once each (`hint()`), including one when nothing small enough has been nearby for 6 seconds (`lostCheck()`). Menu: Resume, Return to Start (back to the start, keeping the size), Settings, Quit to Title. Esc opens and closes the menu (and closes Settings first).
- **Saving** (`save()`, `retroHole.save` for the normal game and `retroHole.saveQuick` for Quick Game, `SAVE_KEYS`: `{ v: 1, x, z, xp, eaten }`): every 5 seconds, on pause and on leaving. Continue puts the hole back; the eaten things are not saved, the map is made again.
- **Sound** (`blip()`, `sfx()`): a few tones, no files.
- **For the tests:** `window.__rh` gives the state, the hole (`H`), the cells, the things falling, the frame count, what the last frame drew, `teleport(x, z)`, `setXp()`, `nearestEdible(re)` (only types matching `re`), `fading` (how many things are dissolving), `BOTS`, `active`, `dying` and `VIS` (the bots and their visuals), `UN` (the shader's holes), `standing()`, `poolSlots()`, `steer(ax, ay)`, `speedRef()`, `home()` and the settings. Add to it as the game grows.
